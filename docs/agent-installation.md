# Команды для сопровождаемой установки

Это практическое дополнение к [AGENTS.md](../AGENTS.md). Агент выбирает подачу уровня 1/2/3, подставляет обнаруженные пути/ОС и выполняет этапы с проверками. Не отправляйте пользователю весь документ как одну инструкцию. Установка на существующий сервер начинается с инвентаризации и резервной копии, а не с создания новой базы.

## 1. Подготовка

```text
git clone https://github.com/alexnolmann/nol-my-homecenter.git
cd nol-my-homecenter
```

Если checkout уже есть, проверьте его remote и локальные изменения; не выполняйте reset/clean ради повторения инструкции. Сначала прочитайте корневой AGENTS.md. Установка не требует доступа к приватному репозиторию автора.

Запишите без секретов: ОС и shell, путь checkout, PHP CLI/веб, MySQL, выбранный адрес сайта, Android/API, способ установки APK и нужные функции. В текущей реализации мигратор проверяет MySQL **8.4.x**, а не просто наличие SQL-сервера.

```text
php -v
php --ini
php -m
```

Для Windows проверьте `$PSVersionTable.PSVersion` в `pwsh`. CLI может использовать другой PHP, чем OSPanel. Если Composer жалуется на temp, настройте доступный локальный временный каталог; не отключайте проверки сертификатов или разрешения всего диска.

## 2. Зависимости и конфигурация

Из корня checkout:

```text
composer install --working-dir=server --no-interaction --prefer-dist
php tools/setup/init-local.php
php tools/setup/init-secret-key.php
```

`init-local.php` нужен для выбранного **development**-варианта; существующий файл он сохраняет. Заполните локально настоящие параметры новой выделенной базы в `server/private/config/local.php`. Сохраните сгенерированный токен: не заменяйте весь файл бездумным примером из инструкции. Для рабочего LAN-развёртывания можно явно установить `fixtures => false`, оставив `features.home=false`.

Для **production** используйте `APP_ENV=production` и `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` в окружении **веба и CLI/сборщика**. `local.php` не переопределяет production-параметры БД. Не кладите секреты в shell history или tracked `.osp`/PHP-шаблоны. На Windows путь/способ хранения окружения зависит от версии OSPanel; настройте именно выбранный сайт.

Ключ по умолчанию — `.local/h2/secrets/master.key`, 32 байта. Можно выбрать внешний путь через `MC_SECRET_KEY_PATH`, одинаковый у всех процессов. `init-secret-key.php` создаёт только путь по умолчанию. Если ключ уже задан снаружи, проверьте существующий файл и доступ к нему; не создавайте вместо него второй ключ. Новая собственная база и ключ не являются копиями данных автора.

```text
php tools/setup/migrate.php
```

Ожидается exit code 0 и сообщение о применённых миграциях. При повторном запуске число может быть нулевым. Не редактируйте старые миграции/checksum и не очищайте таблицы, чтобы обойти ошибку. Создание схемы и SQL-пользователя выполняется средствами обнаруженного MySQL/OSPanel: отдельная схема, права только на неё, секрет вводится локально.

## 3. Первичная инициализация сервера

**Сначала определите, новая ли это установка.** Для существующей базы проверьте состояние и сделайте резервную копию. Если прежний `server_id` или ключ утрачен, восстановите его из резервной копии, а не создавайте новую идентичность под видом ремонта.

Миграции создают таблицу `app_state`, но не строку идентичности. Без `app_state(id=1, server_id=...)` первый пользователь может войти в админку, но сопряжение планшета не завершится. Для добавления финансовых инструментов также нужны интеграции `cbr` и `moex_iss`; их отсутствие приводит к `Fixed provider is not initialized`.

### Обычная новая установка: без фиксированного города и модели планшета

В новой выделенной базе после миграций создайте игнорируемый `.local/install/bootstrap-server.php` со следующим содержимым. Этот файл должен лежать **именно** на указанной глубине относительно корня checkout; он читает выбранную реальную конфигурацию без записи паролей в скрипт. Перед запуском агент проверяет назначение базы. Код добавочный: при повторе сохраняет имеющуюся идентичность и существующие интеграции, не трогает город/планшеты/котировки.

```php
<?php
declare(strict_types=1);
$root = dirname(__DIR__, 2);
$config = require $root . '/server/private/bootstrap.php';
$db = new MediaCentre\Storage\Database(MediaCentre\Storage\Connection::open($config));
$state = $db->one('SELECT server_id FROM app_state WHERE id=1');
if ($state === null) {
    $db->query('INSERT IGNORE INTO app_state(id,server_id) VALUES(1,?)', [MediaCentre\Shared\Uuid::random()]);
}
foreach (['cbr' => 'official', 'moex_iss' => 'public_delayed'] as $type => $mode) {
    if ($db->one('SELECT id FROM integrations WHERE type=? LIMIT 1', [$type]) === null) {
        (new MediaCentre\Integration\IntegrationRepository($db))->create(
            MediaCentre\Shared\Uuid::random(), $type, ['data_mode' => $mode]
        );
    }
}
if ($db->one('SELECT server_id FROM app_state WHERE id=1') === null) {
    throw new RuntimeException('Server identity not initialized.');
}
echo "Server identity and fixed finance sources initialized.\n";
```

Выполните один раз из корня:

```text
php .local/install/bootstrap-server.php
```

Не запускайте два bootstrap-процесса параллельно. Не переносите этот локальный скрипт, рабочую конфигурацию или базу в webroot. Если хочется сделать из него постоянный штатный инструмент проекта, это отдельное изменение кода с тестами; обычная установка этого не требует.

### Альтернатива: существующие development-помощники

Только на новой **development**-установке можно вместо локального bootstrap выполнить:

```text
php tools/setup/init-panel.php
php tools/setup/init-finance.php
```

Первый скрипт создаёт идентичность сервера и шаблон **ASUS K014 / Санкт-Петербург**, второй — фиксированные источники, USD/EUR/CNY и SBER/GAZP/LKOH в списке шаблона. Это исходные значения разработки, не обнаруженные параметры человека. Согласуйте их использование, замените место/список через панель и не запускайте эти помощники как универсальную production-миграцию. Они не загружают придуманные прогнозы или котировки.

## 4. Первый администратор

На PowerShell 7:

```powershell
./tools/setup/bootstrap-admin.ps1 -Login owner -PhpPath php
```

Замените `owner`, если нужен другой логин. Пароль запрашивается скрыто дважды, политика — 12–72 **байта**. На ОС без PowerShell PHP-скрипт принимает логин в argv, а пароль только через stdin. Например, в **Bash с пользовательским TTY**, без трассировки команд:

```bash
set +x
read -r -s -p 'Пароль первого администратора: ' setup_admin_password
printf '\n'
printf '%s\n' "$setup_admin_password" | php tools/setup/bootstrap-admin.php owner
setup_admin_result=$?
unset setup_admin_password
test "$setup_admin_result" -eq 0
```

Это пример для Bash, а не универсальная команда для PowerShell/zsh. Если у агента нет доверенного интерактивного ввода, пользователь выполняет скрытый ввод локально; не заменяйте его передачей пароля в чат. Bootstrap отказывается работать, когда администратор уже существует. Это защита, а не повод удалить пользователя.

## 5. Веб и непрерывный сбор

Сначала [OSPanel/Windows](deployment/os-panel.md) либо адаптированная конфигурация выбранного хоста. Для примера `panel.miniw` и `192.168.50.10` — **подстановки**, агент определяет реальные значения, проверяет DNS/доступ с планшета и объясняет способ HTTP/HTTPS.

Для production проверьте маршруты по текущему `server/private/app/Http/Api.php`, а не только по старому Linux-шаблону: в частности ручное обновление погоды, климат, фото и музыка должны пройти через нужный FastCGI endpoint. Важны `Authorization`, идентичность сервера, разрешение админки, внутренний `__music_file`, лимиты multipart и время обработки фото. Docker-шаблон не превращается в полноценную установку только после `up`.

Запустите долгоживущий процесс с конфигурацией той же установки:

```text
php server/bin/console.php maintenance
```

Другим терминалом:

```text
php server/bin/console.php check
```

`ready=true` подтверждает базовые расширения, соединение с БД и свежий heartbeat (до 45 секунд). Оно **не проверяет** наличие города/прав, свежесть прогноза, GD/EXIF, маршруты медиа, доступ с Android или звук. Для запуска после выхода агента настройте службу/systemd/планировщик выбранной ОС с корректной учётной записью, рабочим каталогом и окружением. Запишите точные команды управления созданной службой; не угадывайте чужие имена служб.

## 6. Веб-панель и сопряжение

1. Откройте адрес установки `/admin/`, войдите созданным пользователем.
2. «Место и погода»: создайте реальный город, координаты и часовой пояс; выберите доступного поставщика и при необходимости введите свой API-ключ.
3. «Планшеты» → «Подключить планшет»: место, права и необязательное копирование списков. Создайте код непосредственно перед вводом. Подключённого планшета до ввода кода ещё может не быть — он создаётся при сопряжении.
4. Соберите/установите приложение и в его настройках введите **базовый адрес** сервера (без `/admin/`) и код из восьми символов. Проверьте появление версии/heartbeat устройства в панели.
5. Настройте имя реального планшета, радио и нужные модули. Для финансов выберите инструменты в списке самого сопряжённого планшета; при обычном bootstrap готового шаблона списка не будет.

Право «Читать свои настройки и главную» нужно сводке/настройкам; выдавайте права на используемые модули, запись избранного/предпочтений и heartbeat по назначению. Не заменяйте сопряжение фиксированным development-токеном и не используйте демонстрационные API-сценарии как реальные данные.

## 7. APK и проверка результата

Порядок сборки и создания **своего** ключа — [docs/development.md](development.md). На Windows `tools/android/bootstrap.ps1 -InstallSdk` устанавливает SDK; согласие с лицензией получается у пользователя отдельно. На Linux/macOS настройте системные `JAVA_HOME`/`ANDROID_HOME` и используйте Wrapper, а не Windows-скрипты с `.exe`/`.bat`.

Для обычного использования собирайте и подписывайте release собственным постоянным keystore. Debug предназначен для проверки и имеет отдельный `.dev` пакет. Наличие release-файла не означает наличие подписи: перед установкой проверьте `apksigner verify --min-sdk-version 19`. На старом Android нужна совместимая v1-подпись. Если уже установлено приложение, проверьте пакет/подпись и возможность `adb install -r`; удаление — только согласованная отдельная операция.

Считайте установку проверенной только когда выполнены обязательные пункты:

| Проверка | Подтверждение |
| --- | --- |
| Сервер и сборщик | Панель открывается, `ready=true`, управляемый сборщик продолжает работать после выхода из терминала |
| Сопряжение | Приложение запускается на реальном Android, принимает сервер/код, панель получает heartbeat/версию |
| Реальные данные | Правильный город и настоящий прогноз со статусом; ручное обновление проходит полный маршрут |
| Звук, если нужен | Одна реальная станция слышна; stop/громкость проверены, итоговая громкость согласована |
| Выбранные дополнительные функции | MP3 воспроизводится и перематывается, фото показываются, выбранные финансы/датчики проверены; отсутствующее оборудование не объявлено проверенным |
| Повторный запуск | Приложение сохраняет подключение, серверные службы восстанавливаются согласованным способом |
| Передача пользователю | Есть памятка с адресом, путями, командами управления, планом резервного копирования и честным списком оставшихся ограничений |

Полный CI — отдельная задача на тестовой базе, не способ настроить пользовательскую рабочую схему. Если до физического Android нет доступа, пометь этап «ожидает действия пользователя», дай конкретный шаг и продолжай после ответа. Не заверши сопровождение одной ссылкой на APK или просьбой «дальше прочитайте README».

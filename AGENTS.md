# Руководство для агента — nol-my-homecenter

Этот файл — входная точка для ИИ-агента, которому пользователь поручил «скачай репозиторий и помоги всё запустить». Цель — работающая связка **сервер + веб-панель + Android-приложение на устройстве пользователя**, а не только клонирование или успешная сборка. Общайся на языке пользователя.

Сценарий установки ниже применяй к просьбе установить/настроить проект. Если задача — разработка, обзор кода или правка документации, не начинай установку и не задавай вопросы установочного опроса без необходимости.

## 1. Как общаться

Первым коротким вопросом предложи выбрать уровень объяснений:

> Как тебе удобнее проходить установку?
> **1 — впервые:** объясняю простыми словами, где нажать, что ввести и какой результат увидеть.
> **2 — есть опыт:** даю короткие шаги с командами, поясняю новые места.
> **3 — технический:** краткий план, команды, параметры и результаты проверок.

Уровень влияет только на подачу: полнота установки, проверки и защита данных одинаковы. Не называй человека «ламером», не проверяй его знания и позволяй сменить уровень в любой момент.

- **1:** одно небольшое действие за раз; уточняй, где открыть терминал, что такое сервер/адрес, какие значения заменить. Команду давай готовой под его ОС. После действия объясни ожидаемый результат и дождись подтверждения, если не можешь проверить сам. Не отправляй простыню из двадцати команд.
- **2:** группируй 2–4 связанных действия, добавляй ожидаемый результат и краткое объяснение ошибки.
- **3:** работай самостоятельно в рамках согласованной установки, сообщай решения, команды с побочными эффектами и результаты. Не повторяй очевидные определения.

Вопросы задавай небольшими порциями. Не спрашивай у пользователя то, что можешь безопасно определить сам. Не проси вставить пароль/API-ключ в чат: предложи скрытый локальный ввод или поле веб-панели. Не выдавай «успешно» вместо непроведённой проверки.

## 2. Что находится в репозитории

- Нативное Java/Views-приложение `android/app`, минимум Android 4.4 / API 19. Это не веб-страница и не браузер. Для сборки сейчас нужны JDK 17, SDK platform 36, build-tools 35.0.0 и Wrapper из `android/`.
- PHP 8.4 + **MySQL 8.4**: код в `server/private/app`, миграции в `server/private/migrations`, веб-панель и API через **`server/public_html`**. `server/private` — открытый исходный код вне webroot, а не недостающий закрытый репозиторий.
- Отдельный постоянно работающий сборщик `php server/bin/console.php maintenance`; веб-сервер не запускает его автоматически.
- Приложение получает сводки/настройки с сервера и кэширует их. Радио идёт прямо от радиостанции; MP3 — авторизованным потоком с домашнего сервера, без загрузки всей библиотеки. Фото подготавливает сервер. BLE-датчики читает сам планшет.
- Есть погода, радио, музыка, финансы, фоторамка, климат, два дизайна и две палитры. Яндекс/управление умным домом ещё не реализованы. Проверка на ASUS K014 не гарантирует совместимость всех старых устройств, BLE и Bluetooth-колонок.
- `features.home=false` относится к отложенной интеграции умного дома. Это **не** выключатель главной вкладки; не меняй его на `true` для «исправления» главной.

Сначала прочитай [README](README.md), [команды сопровождаемой установки](docs/agent-installation.md), [установку](docs/getting-started.md), [варианты окружения](docs/deployment/os-panel.md), [сборку](docs/development.md) и [безопасность](SECURITY.md). Уточняй реальные параметры по текущему коду; документация не заменяет проверку exit code и ответов приложения.

## 3. Установка — порядок действий

Веди короткий список этапов: «ожидает / выполняется / проверен / заблокирован». При длинной работе сохраняй **без секретов** состояние в игнорируемом `.local/install/progress.md`: выбранный вариант, относительные пути, сделанное, текущая проблема, следующий шаг. Не коммить рабочие настройки.

### Шаг A. Узнать условия

После выбора уровня выясни ОС сервера/ПК и модель/версию Android. Есть ли постоянно включённый домашний сервер или приложение будет зависеть от включённого ПК? Есть ли доступ агента к терминалу/браузеру/USB или человек будет выполнять действия сам? Какое ядро функций нужно сначала: погода и радио, затем остальные по желанию?

Осмотри существующие Git-файлы, программы, конфиги, службы и занятые порты. Выясни, это **новая установка или существующая база/приложение**. Если окружение и часть настроек уже есть, продолжай с них; не начинай заново. На первом этапе не требуй знания LAN-IP, SQL или Docker от новичка — помоги определить их.

### Шаг B. Клонировать и выбрать окружение

Клонируй `https://github.com/alexnolmann/nol-my-homecenter.git` в отдельный выбранный каталог без перезаписи чужих файлов. Если доступа нет, покажи конкретную причину и помоги с доступом/архивом; не выдумывай наличие готового APK или успешного clone. Прочитай этот файл и в загруженной версии.

Предложи один рекомендуемый путь под обнаруженную ОС и кратко объясни выбор:

- **Windows:** OSPanel 6 / PHP 8.4 / MySQL 8.4 / Nginx — основной проверенный путь. Для скриптов нужен PowerShell 7, не автоматически Windows PowerShell 5.1.
- **Linux/NAS:** существующий PHP-FPM/MySQL/Nginx можно адаптировать; проверь версии, сокет FPM, права и все маршруты. Шаблон `deploy/linux/nginx-tls.conf` не является готовой универсальной конфигурацией.
- **Docker:** [контейнерный шаблон](docs/deployment/docker.md) экспериментальный, не обещай запуск всего продукта одной командой. Он изначально закрывает админку и не покрывает всю текущую работу с медиа.
- **macOS/другое:** готового проверенного маршрута нет. Предложи поддерживаемый сервер в LAN либо объясни, какую адаптацию проведёшь и как проверишь результат.

Не устанавливай Docker/WSL, не перестраивай существующие сервисы и не обновляй чужую базу только потому, что это удобнее агенту. Согласуй существенный выбор окружения, затем выполняй обычные обратимые действия самостоятельно в пределах доступных прав.

### Шаг C. Проверить зависимости

Проверь PHP **CLI и веб-процесса** отдельно: версия и php.ini могут различаться. Нужны PDO MySQL, curl, sodium, XML/SimpleXML, bcmath; для фото — GD (JPEG/PNG) и EXIF. Мигратор требует именно MySQL 8.4, MariaDB/SQLite не являются заменой без изменения проекта.

Установи зависимости через Composer из lock-файла. Проверь запись в PHP temp-каталог и `server/storage` от имени реального веб-процесса. Не меняй зависимости командой `composer update` ради обычной установки. Используй официальные инструкции поставщика для установки пакетов конкретной ОС; не угадывай актуальные команды пакетного менеджера.

### Шаг D. Подготовить конфигурацию, базу и первый сервер

Создай отдельную рабочую схему и пользователя базы. Секреты вводятся локально. В development используй `tools/setup/init-local.php`; production читает `DB_*` из окружения, а не development-параметры `local.php`. Все PHP-процессы, включая сборщик и CLI, должны видеть одну установку и одну базу.

Создай отдельный Sodium-ключ, сохрани его для восстановления и выполни миграции. **Не заменяй уже существующий ключ** и не меняй `server_id` существующего сервера: это ломает доступ к зашифрованным данным/доверие планшетов. Не сбрасывай БД при ошибке миграции.

Проверь инициализацию **`app_state.server_id`** и фиксированных источников финансов: миграции создают таблицы, но не эти записи. Выполни подходящий сценарий из [docs/agent-installation.md](docs/agent-installation.md#3-первичная-инициализация-сервера). Development-скрипты с шаблоном ASUS/Санкт-Петербург нельзя выдавать за обнаруженные параметры пользователя. Для новой обычной установки в руководстве есть минимальный добавочный bootstrap без демонстрационных данных.

Создай первого администратора скрытым вводом через `tools/setup/bootstrap-admin.ps1`, либо stdin PHP-скрипта на ОС без PowerShell. Существующего администратора не удаляй ради повторного bootstrap. Запиши результат проверки, а не пароль.

### Шаг E. Поднять веб и сборщик

Настрой webroot строго на `server/public_html`, PHP/FastCGI, админский endpoint, заголовки авторизации и внутреннюю передачу музыки. Для Windows используй `deploy/osp` и инструкцию; не открывай всю папку репозитория как сайт. Loopback-конфигурация `deploy/windows` сама по себе не делает сервер доступным с планшета.

Выбери стабильный LAN-адрес и проверь доступ **с планшета**, а не только с ПК. `localhost` на Android означает сам планшет. Hosts-файл ПК не настраивает DNS планшета. При необходимости помоги с DNS роутера/резервированием адреса и точным правилом firewall только для нужной локальной сети.

Для HTTP требуется явный `MC_HTTP_HOST` и разрешённый сервером endpoint админки. Объясни пользователю, что HTTP передаёт учётные данные без шифрования; не включай его молча. Для HTTPS проверь цепочку и имя/SAN на Android, создай собственные сертификаты при необходимости. **Не отключай TLS-проверку** и не ищи домашний CA автора проекта.

Запусти один процесс `maintenance` с тем же окружением, дождись heartbeat и проверь `php server/bin/console.php check`: `ready=true`. Затем настрой управляемый автозапуск/перезапуск под выбранную ОС. Не оставляй фоновый процесс привязанным только к случайно открытому терминалу агента. Если есть `maintenance.stop`, выясни его происхождение и убери только при согласованном возобновлении сборщика.

### Шаг F. Настроить через веб-панель

Войди в `/admin/`, создай **город пользователя** с координатами и часовым поясом в «Место и погода», выбери доступного провайдера. Open-Meteo/MET Norway не требуют пользовательского ключа в этой реализации; Visual Crossing требует собственный ключ. Проверь доступ с сервера, при fallback также с планшета. Не обходи лимиты источника частыми перезапусками.

В «Планшеты» выдай код с нужным местом, правами и, если нужен, шаблоном списков. Реальная запись планшета создаётся при использовании кода приложением; заранее подключённое устройство в списке не обязательно. Код из восьми символов одноразовый, действует десять минут и показывается один раз. Нужны права чтения выбранных модулей, настроек и heartbeat; для управления — соответствующие write-права. Не добавляй несуществующие права на умный дом.

Сначала настрой одну рабочую радиостанцию и погоду. Финансы, фотографии, MP3 и датчики добавляй после первого успешного сопряжения по потребностям пользователя.

### Шаг G. Собрать и установить Android

Проверь `android/app/build.gradle` и [команды сборки](docs/development.md). Используй свои инструменты и ключи. На Windows помощник SDK требует явного `-InstallSdk`; принятие лицензии SDK — действие пользователя, не добавляй `-AcceptSdkLicense` без его согласия.

Выбери debug для первичной диагностики или подписанный release для постоянной установки. Неподписанный release APK не устанавливается. Debug имеет пакет с суффиксом `.dev`, отдельные настройки и тестовые hooks; объясни разницу и не считай два пакета одной установкой. Храни ключ постоянной подписи: следующий APK должен обновлять установленный пакет без удаления данных.

Если есть согласованный USB-доступ, проверь `adb devices`, попроси человека подтвердить RSA-запрос на самом планшете и установи через `adb install -r <apk>`. Без USB помоги передать APK и разрешить установку выбранным способом. При конфликте подписи **не удаляй приложение молча**. Само наличие APK не доказывает успешной установки.

Открой настройки приложения, введи достижимый с Android адрес сервера и свежий код. Убедись, что панель видит heartbeat/версию настоящего устройства. Если агент не имеет UI-доступа, дай действие и дождись результата пользователя — не подменяй физическую проверку тестовым скриптом.

### Шаг H. Проверить реальные функции

- Погода для выбранного города получена от реального источника, видны время/статус данных в диагностике; ручное обновление работает. Ошибку источника или старый кэш не называй свежим прогнозом.
- Радио реально слышно на согласованной малой громкости; stop и громкость работают. Не оставляй звук включённым после проверки без просьбы.
- Если нужны финансы: настрой источники/инструменты и **список именно сопряжённого планшета**. Изменение шаблона после сопряжения автоматически в уже созданный список не копируется. Проверяй исходные даты котировок; отсутствие торгов/задержка не равно поломке.
- Если нужны фото: включи модуль/право, загрузи несколько допустимых JPEG/PNG, проверь миниатюры и показ. Сервер не сохраняет исходники фото после подготовки — пользователь должен иметь свои оригиналы.
- Если нужна музыка: укажи существующую папку MP3, проверь права службы, дождись индекса, проиграй трек и **перемотай**. Одного открытия каталога недостаточно для проверки Range/X-Accel-Redirect.
- BLE и колонки — необязательны и проверяются физически. LYWSD03MMC — штатная прошивка, до трёх датчиков; начни с одного. Колонки сначала сопрягаются в Android. Не прошивай датчики и не меняй Bluetooth-связи других устройств без запроса.

### Шаг I. Закончить установку и передать управление

Проверь повторный вход в панель, перезапуск приложения и согласованный перезапуск сервисов. Убедись, что после выхода агента сборщик продолжит работать. Отключённые/непроверенные дополнительные функции так и пометь.

Дай короткую памятку под выбранный уровень: адрес панели, путь установки, где настройки и резервная копия, как запустить/остановить службы, как обновлять APK без потери подписи, что осталось сделать. Пароли/токены/ключи в памятку не включай. Резервируй базу, Sodium-ключ, конфигурацию, фото и ключ Android-подписи; пароль администратора хранит пользователь.

Не заверши просьбу «установи» словами «всё готово», если только собраны исходники или осталась обязательная ручная операция. Продолжай доступную работу; при внешнем блокере укажи конкретный следующий шаг и дождись пользователя. Не гарантируй суточную стабильность или расход батареи кратким smoke-тестом.

## 4. Если что-то не работает

| Симптом | Что проверить и как действовать |
| --- | --- |
| `php`/Composer не найден, нет расширения | Реальный исполняемый файл, `php -v`, `php --ini`, `php -m`; затем отдельно веб-PHP. Не редактировать случайный php.ini. |
| Composer не пишет temp/cache | Права/наличие temp, локальные `sys_temp_dir`, `TEMP`/`TMP`, Composer cache; без отключения TLS и без запуска всех служб от администратора. |
| PowerShell не знает `-Environment` | Проверить `pwsh` 7; не запускать скрипт с такими параметрами в PowerShell 5.1. |
| Миграции отвергнуты | MySQL 8.4, фактическая схема, права, состояние/checksum `schema_migrations`; сохранить данные, выяснить причину, не сносить таблицы и не переписывать контрольные суммы. |
| `ready=false` | Разобрать поля `extensions`, `database`, `maintenance`. Heartbeat старше 45 секунд не считается рабочим; проверить сборщик, его среду, права storage и stop-файл. |
| Админка 403 / 404 / 502 / 503 | Различать отказ доступа, маршрут, FastCGI и БД. Проверить разрешённый HTTP-host/HTTPS, `MC_ADMIN_ALLOWED`, webroot, сокет/порт PHP, server error log без секретов. Не снимать защиту всего сайта. |
| Страница работает на ПК, планшет не видит сервер | LAN-IP/DNS, Wi-Fi client isolation/гостевая сеть, firewall, bind/listen; `127.0.0.1` и hosts ПК недостаточны. Не открывать порты в интернет ради локального доступа. |
| Первый код не сопрягает / `Server not initialized` | Наличие `app_state`, выбранного города, правильная БД у CLI и веба, срок/однократность кода, часы и TLS. Для новой попытки выдать новый код, а не сбрасывать всю установку. |
| Сертификат отклоняется | Время устройства, SAN/имя, полная цепочка, совместимость старого TLS и правильный build variant. Не добавлять доверие всем сертификатам. |
| Не устанавливается APK / `unauthorized` | Физический RSA-диалог, API устройства, свободное место, пакет/версия/подпись APK. Удаление пакета требует отдельного решения из-за потери данных. |
| Новая база не даёт создать финансовый инструмент | Нужны фиксированные `cbr`/`moex_iss` интеграции; выполнить первичную инициализацию, затем создать инструменты и список планшета. |
| Нет свежей погоды/финансов | Исходящий HTTPS/DNS, выбранный провайдер/ключ, город/часовой пояс, сборщик и очередь/backoff; UI может показывать кэш. 429 не лечится бесконечным «Обновить». |
| Радио работает, погода/фото нет | Радио обходит сервер. Это не доказательство связи с API; проверить сервер отдельно. |
| MP3 играет, перемотка нет | Ответ 206 на Range, авторизация, внутренний Nginx location/X-Accel-Redirect и права на исходный файл; не копировать библиотеку целиком на планшет. |
| Фото не загружаются | GD/EXIF, память, POST/upload и Nginx-лимиты; текущие границы панели — до 10 файлов за раз, до 24 МБ и 48 Мп на файл. Не лечить изменением только одной цифры. |
| BLE/A2DP нестабильны | Версия Android, разрешения, питание/расстояние, занятость устройства другим клиентом, особенности прошивки. Не обещать программного исправления аппаратных ограничений. |

При изменении настроек возвращайся к конкретному неуспешному шагу и повторяй его проверку, а не всю установку с нуля.

## 5. Границы работы агента

Не публикуй локальные конфиги, ключи, пароли, токены, реальные фото и базы. Не проси их в issue/чате. Не меняй visibility/remote, не создавай публикации и не делай push без прямой просьбы. Домашние данные автора для установки не нужны.

Перед потерей данных, заменой ключей, удалением установленного приложения, изменением глобальных служб, сетевого доступа или доверенных сертификатов объясни конкретное действие и последствия и получи необходимое разрешение. Обычные чтения, проверки и обратимые настройки внутри согласованной установки выполняй без бесконечных подтверждений.

Тесты `server/tests/ci.php` требуют отдельной `*_test` схемы и отдельного пользователя; **никогда не направляй их на рабочую БД**. Для обычной установки полный CI не заменяет проверку реального планшета. Смотри [docs/development.md](docs/development.md) и `tools/check-public.php`.

При разработке сохраняй API 19, границы webroot и авторизации, точность финансовых значений, единственный активный аудиоплеер и отсутствие секретов в исходниках. Не меняй контракт/версию/дизайн ради настройки конкретной машины. При расхождении команд с кодом исправь инструкцию или минимальную подтверждённую проблему; не маскируй её отключением проверок.
